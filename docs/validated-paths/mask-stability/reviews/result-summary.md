# Mask 稳定性验证结果

## 结论

本轮路线未达到冻结的稳定性门槛，但验证出了清晰的能力边界：

```text
image-2 能理解场景语义并选择大致合理的角色落位区域，
也能把角色生成在黑圆附近；
但不能可靠生成固定 108px Mask，
也不能保证角色严格包含在 Mask 内或保持 Mask 外像素不变。
```

因此不建议在下一阶段继续优化“让生图模型自己画固定大小 Mask”的 Prompt。更有希望的路线是：

```text
视觉模型输出语义目标 + 候选中心点/允许区域
→ 规则检查可站立性与遮挡
→ 确定性程序绘制固定 108px Mask
→ image-2 根据 Mask 生成角色
→ 人工或视觉模型复核角色与背景
```

## 完成范围

- 20 张可追溯的 Wikimedia 风景候选，含来源和许可元数据。
- 从候选中筛选 8 个任务组，每组 2 个空间风险不同的元素。
- 8 张统一 Neva 手绘语言的 1376x768 无角色场景。
- 32 个独立实验单元：`8 组 × 2 元素 × 2 轮`。
- 32 次 Mask 生成与 32 次角色生成，共 64 次 `gpt-image-2` 图片调用。
- 32/32 Mask 输出和 32/32 角色输出均可解码，未出现 Provider 失败。
- 自动测量、8 张分组接触表和 32 条人工评分均已保存。

## 自动测量

| 指标 | 结果 |
|---|---:|
| 目标直径 | 108px |
| 实测最小 / 中位数 / 均值 / 最大 | 32.74 / 64.96 / 67.94 / 128.21px |
| 相对目标的平均绝对误差 | 42.68px |
| 落在 108±10px 内 | 1/32 |
| 同元素两轮圆心漂移中位数 / 均值 / 最大 | 41.05 / 44.34 / 85.75px |
| 同元素两轮直径差中位数 / 均值 / 最大 | 10.50 / 22.75 / 62.79px |
| Mask 阶段圆外像素 MAE 均值 | 13.29 |
| 角色阶段原 Mask 圆外像素 MAE 均值 | 22.28 |

圆外像素差异说明两次编辑都发生了不同程度的全图重绘。该指标对笔触细节敏感，不能单独等同于肉眼可见破坏；但它足以否定“只改变圆内像素”的严格承诺。

## 人工复核

评分为 1–5 分，`5` 表示满足冻结要求。完整逐项记录见 `manual-review.csv` 和 `manual-review-ratings.json`。

| 维度 | 均分 | 判断 |
|---|---:|---|
| Mask 语义位置 | 4.31 | 多数能找到正确地标附近区域 |
| Mask 固定尺寸 | 2.25 | 明显失败，仅 4/32 人工尺寸评分达到 4 分 |
| Mask 可站立性 | 4.31 | 大多数合理；海岸和远岸出现错误 |
| 单圆清晰度 | 5.00 | 32/32 都生成单个清晰黑圆 |
| 角色存在与身份可辨 | 3.12 | 中大尺寸结果可辨，小圆结果过小 |
| 角色严格服从 Mask | 2.44 | 32/32 均有不同程度超出原圆范围 |
| 角色接地 | 4.00 | 多数脚底关系自然 |
| 指定互动动作 | 2.44 | 24/32 被标记为互动不匹配，多数退化为普通站立 |
| Neva 风格与场景保持 | 3.00 | 场景统一，角色仍偏 Q 版动漫贴入感 |

按 Spec 的元素门槛计算：两轮中至少一轮 Mask 平均分 ≥4 且角色平均分 ≥4。最终通过 `0/16` 个元素，因此整条路线不通过。

这并不意味着实验没有正向结果：28/32 个 Mask 的语义位置评分达到 4 分以上，14/32 个角色的身份可辨评分达到 4 分以上。失败主要集中在固定像素尺寸、严格 Mask 包含、动作执行和像素级背景保持，而不是场景理解本身。

## 已验证与未验证

本轮已经验证：

- Neva 风格场景可以从不同经典构图参考中统一生成。
- 模型能根据自然语言描述在复杂场景中找到多数目标元素附近区域。
- 黑圆作为角色落位信号有效，32 张结果都在圆心附近生成了单一角色。
- 角色大小会受到 Mask 大小影响，说明 Mask 可作为软尺度信号。

本轮明确未达到：

- 固定 108px 的 Mask 尺寸执行。
- 同一目标两轮的具体圆心复现。
- 角色完全包含于 Mask 的硬约束。
- 指定轻量互动动作的稳定执行。
- Mask 外像素完全不变。
- Q 版角色完全融入 Neva 的块面、笔触和材质语言。

本轮没有验证：

- 专门的视觉语言模型直接输出坐标的精度。
- 程序绘制固定 Mask 后，角色尺寸是否会稳定。
- 角色实际 bbox、脚底锚点的自动检测。
- Unity 坐标转换、点击热区和运行时状态切换。

## 下一验证建议

优先做一个更小的对照实验，不需要再次生成 8 组全量场景：

1. 从本轮选 4 个代表场景：G01 海岸失败、G03 瀑布成功、G06 开阔草坡、G07 复杂森林。
2. 让视觉模型只输出 3 个候选中心点与可站立理由，不让它画圆。
3. 程序在每个中心点绘制完全一致的 108px Mask。
4. 对每个固定 Mask 生成 2 轮角色，比较角色 bbox、身份、动作和背景保持。
5. 若角色仍普遍超圆，再把 Mask 从“完整角色容器”改成“脚底锚点/落位提示”，不要把它误当硬边界控制。
