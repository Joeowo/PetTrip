美术生成 Agent
三条技术路线

三条路线拥有相同的玩家输入与游戏输出，真正的分歧在于：场景结构是在生图前被规划、在生图后被恢复，还是由概念图与关键资产共同完成。

质量优先，性能后置。

先比较最终游戏场景的视觉效果、需求还原和风格一致性；只有质量接近时，才比较端到端时间与 Agent Token 消耗。

Shared Foundation

共同前置流程

为了公平实验，三条路线必须共享同一份玩家原始需求、澄清结果和 WorldSpec，并最终输出相同格式的 SceneSnapshot。

01 玩家需求

永久保留原始描述，作为需求还原审核的基准。

02 澄清 Agent

只补齐对最终画面影响最大的缺失信息，限制一至两轮。

03 WorldSpec

锁定世界主题、情绪、地貌、色板、地标和禁止项。

04 美术生产

三条路线从此处产生分歧，采用不同的结构与生成顺序。

05 SceneSnapshot

统一打包为客户端可加载、可存档、可共建的场景版本。

WorldSpec 的职责

它表达“这是一个怎样的世界”，而不是规定每棵树的位置。三条管线共用同一个版本，才能把实验差异归因于生产路线本身。

场景打包

ScenePlan 在生图前确定什么

  • 相机、透视与整体构图
  • 前景、中景与远景层级
  • 地面及角色活动区域
  • 核心地标位置和比例
  • 遮挡与渲染排序关系
  • 留言板、拍照点等交互点
  • 可用于共建的合法槽位
  • 每项资产的生成约束

推荐生成粒度

不把场景拆成每棵树、每块石头。远景与中景可以整体生成，核心地标、共建物、交互物单独生成；普通装饰优先复用素材库。所有资产共享色板、光照方向、透视和风格参考。

审核重点

先检查单项资产的风格、透明底、尺寸与锚点，再检查组装后的拼装感、构图、角色空间和共建槽位。结构正确并不等于画面自然，最终整体审核不可省略。

主要优势

  • 游戏结构和分层确定性最高
  • 共建、动画、碰撞与独立修改容易
  • 不强依赖自动分层模型
  • 最适合长期扩建与维护

主要风险

  • 独立素材容易出现拼装感
  • 透视、光照和颗粒度可能不一致
  • 生成任务较多，前期工程复杂

更适合

  • 共建和扩建是核心能力
  • 强调长期可编辑性
  • 已有较成熟的基础素材库

整体生图仍需基础构图约束

  • 中部保留横向活动道路
  • 地标处于明确视觉中心
  • 预留未来共建空间
  • 前景不得大面积遮挡主路径
  • 前中远景关系清晰
  • 禁止元素和风格边界明确

两次审核承担不同职责

第一次在分层前判断画面是否值得继续投入，重点是视觉效果、需求还原和构图。第二次在分层补全后检查边缘、破洞、残影、穿帮、角色活动区域和共建空间，重点是游戏可用性。

分层与补全

从完整画面提取远景、中景、主地面、前景遮挡物和核心建筑。被遮挡区域需要局部重绘或扩图补全；分层完成后，再推导碰撞轮廓、交互点、锚点、视差参数与共建候选区域。

主要优势

  • 整体构图、光照和氛围通常最好
  • 更容易快速获得高冲击力画面
  • 前期对复杂布局系统依赖较低

主要风险

  • 分层是在结果中逆向恢复结构
  • 遮挡区域需要额外补全
  • 分层后可能明显损失原图质量
  • 共建位置和独立对象不确定

更适合

  • Demo 优先追求第一眼效果
  • 场景交互与动画较轻
  • 分层模型已验证足够稳定

HYBRID

粗粒度 ScenePlan 只锁定硬约束

  • 主地面和活动空间
  • 地标的大致位置与比例
  • 前中远景占比
  • 镜头和透视方向
  • 共建保留区域
  • 不可遮挡的关键区域

只拆真正需要控制的内容

天空、云海和中景小镇可保留为大图层；核心地标参考概念图单独重生成；地面与道路可结合模板重做；留言板、共建物和动画对象独立生产。纯装饰内容不影响交互时，无需为了“彻底分层”增加复杂度。

审核重点

对照概念图检查最终游戏组装是否保留原始氛围，同时确认重生成对象自然融入、没有重复阴影或残留痕迹，主地面和共建区真实可用。

主要优势

  • 视觉效果通常接近画面先行
  • 比纯画面先行更容易支持共建
  • 工程投入集中在关键对象
  • 分层失败时存在降级空间

主要风险

  • 流程最长，模型与工具最多
  • Agent 调用和审核成本较高
  • 概念图与独立资产可能不一致
  • 拆分边界不清会让流程膨胀

更适合

  • 既要惊艳画面，也要基础共建
  • 只有少量对象需要独立编辑
  • 团队可接受更复杂的生产链路

Decision Rule

实验后的选择顺序

三条路线使用相同 WorldSpec、相同场景要求和相同模型版本完成实验。先保证最低游戏可用性，再把 Demo 的视觉效果放在首位。

01

先过游戏可用性门槛

场景必须能正常加载，角色活动区域清晰，遮挡关系合理，并保留可用的交互点和共建空间。存在硬伤的结果不进入视觉排名。

02

优先选择效果最好的路线

重点比较第一眼视觉效果、玩家需求还原度和风格一致性。质量存在明显差距时，直接选择视觉质量最高的路线。

03

质量接近再比较性能

依次比较端到端时间、LLM Token、生图次数、分层次数和失败重试次数。成本是第二位，但需要完整记录。

在满足最低游戏可用性的前提下，优先选择最终游戏画面效果最好的路线，而不是流程最简单或成本最低的路线。
