Implementation continued in a dedicated worktree and branch:

The following session 2 capabilities are implemented:

- Authenticated multipart upload at `POST /api/v1/files`.
- PNG and JPEG signature, MIME, extension, byte, dimension, pixel, and decode
  validation before any model call.
- Atomic storage under `data/files/input/`, with only relative paths and metadata
  stored in SQLite.
- Authenticated metadata and content download endpoints with ownership and storage
  root checks.
- Run attachment DTOs using `file_id + purpose`, with ownership, purpose, duplicate,
  and maximum-count validation.
- Atomic `message_files` relationships in the Run creation transaction.
- Provider-neutral `VisionImage` domain input converted only at the Provider boundary
  to OpenAI-compatible `image_url` data URLs.
- Successful historical text remains in context, while only the current Run's images
  are sent to the Vision model.
- A staging-first real validation runner at
  `pilot4mvp2/scripts/verify_session2.py`. It creates a non-sensitive red/blue test
  PNG, validates downloads, runs disguised and oversized negatives, checks SQLite
  for BLOB values, and publishes only redacted evidence.

Locked session 2 limits are 10 MiB, 4096 pixels per side, 20 million total pixels,
PNG/JPEG only, and at most four non-duplicate attachments per Run.
