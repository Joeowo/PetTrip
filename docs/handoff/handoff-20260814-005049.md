## 下一会话实施目标

按最小纵向链路完成会话 3，不引入 Flowise、Redis、Celery、Kafka、多 Agent 编排或 Unity 修改：

1. 扩展 Run DTO，至少支持 `text`、`image` 模态，并保留 `extra="forbid"`。
2. 增加独立 `ImageGenerationProvider` 接口和 OpenAI-compatible 实现。
3. Provider 必须调用 `POST /v1/images/generations`，模型默认配置为 `gpt-image-2`；不要把该模型发到 Chat Completions。
4. 图片请求 Prompt 直接使用用户文本；请求尺寸来自服务配置。
5. 严格解码响应 `data[*].b64_json`，限制解码字节数，使用 Pillow 校验真实格式/宽高/像素数。
6. 等比缩放、居中裁切到配置目标画布，并强制 PNG 输出。
7. 写入 `data/files/generated/`：临时文件、`fsync`、原子移动，保存实际宽高、字节数、SHA-256 和相对路径。
8. 扩展 Worker 支持 image-only 和 text+image；图片 Provider 失败映射 `IMAGE_PROVIDER_UNAVAILABLE`，不自动重试。
9. 成功时在一个事务内提交 assistant message、Run 输出、生成文件元数据、`message_files(role=output)` 和 `artifact.created`/`run.completed` 事件。
10. 任一 Provider/解码/落盘失败时，Run 进入 `failed`，不留下 SQLite 文件记录、`message_files` 或可下载的部分文件。
11. `_run_response()` 只返回 `file_id`、元数据和下载 URL，不返回 Base64、绝对路径、Provider 原始响应或密钥。
12. 补齐会话 3 离线测试；必要时增加脱敏 `verify_session3.py`，真实在线验证需使用服务端环境变量，不将密钥写入仓库。
