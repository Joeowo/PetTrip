# Pilot4MVP2 Agent Service 会话 5 交接

本文档记录会话 5 的组合输出验收结论、测试入口和 Git 边界。实现细节以代码、规格和
脱敏证据为准。

## 当前结论

会话 5 已经通过验收：

- 真实正例上传一张非敏感参考图。
- 同一 Run 返回文本、`scene_draft` `0.1` 结构化数据和规范化 PNG。
- Run 状态为 `queued -> running -> succeeded`。
- 成功事件顺序为 `run.queued -> run.started -> image_generation.started ->
  artifact.created -> message.created -> run.completed`。
- 公共消息历史、事件载荷和 SQLite 记录指向同一个 Run 和助手消息。
- API 测试客户端分别校验非空文本、固定结构化 DTO 和生成图片 DTO。
- 生成图片通过鉴权下载，Pillow、目标尺寸、SHA-256 和重复下载校验均通过。
- 结构化、文本和图片阶段的三个受控失败例均未提交部分助手消息。
- 失败例没有生成文件记录、输出附件关系或磁盘生成文件。
- `validation-report.json` 记录 `passed: true`。

## 本次实现

会话 5 在现有组合执行主链上增加以下可观察性和原子性保护：

- 实现 `GET /api/v1/sessions/{session_id}/messages`。
- 在 `artifact.created` 和 `message.created` 事件中返回同一 `message_id`。
- 当 Run 不再处于 `running` 时，成功事务显式失败，不再静默忽略。
- 启动孤儿清理会删除服务创建的隐藏 `.tmp` 文件，并保留无关隐藏文件。
- 增加固定组合输出 DTO，只从专用字段读取三种输出。

当前图片 Provider 仍按 Pilot 规格直接使用用户文本作为图片 Prompt。参考图进入
Chat/Vision 的结构化和文本调用，但本会话不宣称生成图片执行了 image-to-image 编辑。

## 验证命令

会话 5 定向测试命令如下：

```powershell
python -m pytest `
  pilot4mvp2/tests/test_session5_combined_output.py `
  pilot4mvp2/tests/test_session5_file_cleanup.py `
  pilot4mvp2/tests/test_verify_session5.py -q
```

结果：`19 passed`。

全量回归命令如下：

```powershell
python -m pytest pilot4mvp2/tests -q
```

结果：`89 passed`。当前 Python 环境会输出一个既有的 `requests` 依赖版本警告，不影响
测试通过状态。

真实验收需要同时可用的 Chat/Vision 和 Images Generations Provider 配置：

```powershell
$env:PETTRIP_LOCAL_ENV_PATH = "<path-to-local-env>"
python -m pilot4mvp2.scripts.verify_session5
```

脚本强制图片模型为 `gpt-image-2`。如果没有独立 `IMAGE_BASE_URL` 或 `IMAGE_API_KEY`，
服务配置会按既有规则回退到 Chat Provider 的 Base URL 和 Key。证据目录存在时脚本拒绝
覆盖；任何验证失败都不会发布正式证据目录。
