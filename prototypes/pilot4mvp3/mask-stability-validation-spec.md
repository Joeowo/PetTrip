# Mask 稳定性验证 Spec v0.1

## Problem Statement

PetTrip 需要在一张没有角色的横版场景图中，为指定场景元素选择角色落位，并把这个位置转化为图片模型可以执行的固定大小 Mask。当前未知量不是“图片模型能不能生成一只角色”，而是以下两段能否连续成立：

```text
纯场景图 + 目标元素
→ image-2 生成稳定、准确的固定大小 Mask
→ image-2 依据带 Mask 场景图生成角色场景
```

本 Spec 只做探索验证，不建立生产级编排、数据库、重试、Unity 接口或正式 `scene_package`。

## Solution

从公开可追溯的经典风景图中收集 20 张候选，按构图和元素复杂度人工筛选 8 张作为任务组。每组冻结两个具有明显空间特征的元素，例如灯塔、桥、树、路牌、瀑布、岩柱或台阶。

每个任务组在统一 NEVA 画风和统一 Q 版若叶睦角色条件下进行 2 个元素 × 2 轮实验。每个实验单元包含两个图片模型调用：

1. 基于无角色场景图，在一个元素上生成固定尺寸的黑色圆形 Mask 图；另一个元素不打 Mask。
2. 以该 Mask 图和角色参考条件为输入，生成角色场景图，要求角色主体完全位于 Mask 内并与该元素形成自然关系。

因此全量规模为：8 个任务组、32 个实验单元、64 次图片调用。这里的“4 次/组”指 4 个实验单元，不是 4 次 API 请求。

## User Stories

1. 作为视觉验证人员，我希望每个任务组都有可追溯的原始风景图和来源 URL，以便区分参考构图与模型创作。
2. 作为视觉验证人员，我希望每个任务组都冻结两个有特征的场景元素，以便分别测试不同形状、深度和遮挡条件下的 Mask。
3. 作为 Agent 技术开发者，我希望无角色场景 Prompt 保持统一结构，以便差异主要来自场景构图而不是 Prompt 随意变化。
4. 作为 Agent 技术开发者，我希望每次 Mask 只覆盖一个目标元素，以便单独判断模型的定位能力。
5. 作为 Agent 技术开发者，我希望 Mask 尺寸固定，而不是根据模型结果事后调整，以便测量位置稳定性。
6. 作为角色素材验证人员，我希望所有角色编辑使用同一组若叶睦 Q 版参考条件，以便观察身份和比例是否稳定。
7. 作为人工评审，我希望能并排查看原始场景、带 Mask 场景和角色结果，以便判断 Mask 是否准确以及角色是否越界。
8. 作为项目负责人，我希望每组保留两轮独立实验和失败样例，以便知道结果是能力还是偶然成功。
9. 作为后续 Unity 开发者，我希望记录 Mask 的像素范围、角色实际范围和底部锚点，以便后续验证坐标消费。
10. 作为研究人员，我希望区分“Mask 画得准”和“角色遵守 Mask”两个结论，以便定位失败来自规划、Mask 生成还是图片编辑。
11. 作为美术评审，我希望角色与场景保持 NEVA 的色板、光照和构图关系，而不是只判断角色是否出现在黑圆内。
12. 作为实验执行者，我希望每次调用都记录模型、Prompt、输入图哈希、输出图和人工评分，以便复盘结果。

## Implementation Decisions

### 1. 最高验证接缝

本 Spec 的最高接缝是：

```text
无角色场景图 → 单元素固定 Mask 图 → 角色场景图
```

Agent 的自然语言推理、自动布局求解和 Unity 接入不作为本轮前置条件。Mask 位置可以由实验人员在 Prompt 中指定目标元素，但 Mask 的尺寸、是否只覆盖该元素以及角色是否遵守 Mask 必须由人工审核。

### 2. 参考图来源

候选图来自 Wikimedia Commons 的公开文件页。每张候选至少记录：标题、原图 URL、缩略图 URL、文件页 URL、抓取时间、许可/作者元数据和本地 SHA-256。候选只用于构图和元素分析，不直接复制其画风；实际生成统一使用 NEVA 画风。

20 张候选与筛选记录见 `references/reference-catalog.json`，本地图片见 `references/candidates/`，8 组入选图见 `references/selected/`。

### 3. Neva 统一画风条件

所有 Prompt 以游戏 [Neva](https://store.steampowered.com/app/2420660/Neva/) 的视觉语言为统一画风参考，具体色板由 `docs/neva_palette_guide.html` 提供：

- 手绘 2D 绘本感、粉彩与水粉式块面、可见但克制的纸张/笔触纹理、清晰剪影、电影化横向构图；固定横版 16:9；固定镜头；无 UI、无文字、无人类主体。
- 场景避免通用动漫背景、写实摄影、3D 渲染和高光塑料材质；角色保持 Q 版比例，但其线条、块面、光照和材质必须融入同一 Neva 手绘语言。
- 前景保留低矮地面带和少量循环小元素；中景承担主要建筑、地标或自然主体；后景承担天空、远山、雾气和情绪。
- 每个场景只使用一组主色板：前两色决定情绪底板，第三色负责结构层，第四色负责暗部和轮廓，第五色只作 5%–10% 点睛。
- 角色与场景共享时间、主光方向、色温、阴影强度和材质逻辑。
- 禁止额外人物、文字、水印、Logo、UI、第二只宠物和无关主体。

实验固定使用 Steam 页面官方截图 `references/neva-official/neva-steam-06.jpg` 与 `references/neva-official/neva-steam-14.jpg` 作为纯画风参考。Prompt 明确禁止复制截图中的树木、角色、构图和事件，只继承块面、剪影、笔触、层级和光色处理。

### 4. 角色条件

角色统一为“MYGO!!!!! 若叶睦的 Q 版形象”。Prompt 需要固定：灰蓝短发、标志性发型轮廓、青绿色眼睛、偏冷的制服/舞台服色彩、Q 版头身比、圆润简化的五官和体型。若后续取得团队批准的角色参考图，应将其作为同一输入参考图；本 Spec 不把角色参考图的取得混入 Mask 稳定性结论。

### 5. 任务组

任务组不是按地点平均抽样，而是覆盖 Mask 的主要风险类型。初始 8 组如下，最终元素名称和坐标以 `reference-catalog.json` 为准：

| 组 | 构图类型 | 计划使用的特征元素 | 主要验证风险 |
|---|---|---|---|
| G01 | 海岸开阔横向构图 | 海蚀柱、海岸步道/栏杆 | 远景主体与地面落位 |
| G02 | 山谷纵深构图 | 山口/冰川切面、木桥 | 透视、尺度和地面线 |
| G03 | 森林通道构图 | 林间道路、木阶/瀑布 | 细碎纹理和遮挡 |
| G04 | 湖泊倒影构图 | 湖岸码头、远山/小船 | 水面边界和倒影干扰 |
| G05 | 荒漠曲线构图 | 沙丘脊线、孤树/岩柱 | 低纹理但强轮廓 |
| G06 | 草原横向构图 | 单树、风车/旗杆 | 大面积留白和小目标 |
| G07 | 黄昏城市/小镇构图 | 路灯、屋门/拱门 | 人造结构和光源遮挡 |
| G08 | 雾夜高对比构图 | 灯塔/塔楼、石栏/长椅 | 暗部、雾气和边缘可见性 |

### 6. 实验单元

每组两个元素分别独立测试，两轮使用同一场景图、同一角色条件和同一 Mask 直径：

```text
Gxx-E1-R1: Mask → 角色编辑
Gxx-E1-R2: Mask → 角色编辑
Gxx-E2-R1: Mask → 角色编辑
Gxx-E2-R2: Mask → 角色编辑
```

Mask 任务要求：

- 只在目标元素附近放置一个黑色圆形 Mask。
- Mask 直径为画布短边的 14%，四舍五入到模型可用尺寸；同组两元素、两轮不改变直径。
- Mask 不覆盖目标元素主体，不覆盖第二个特征元素，不跨越明显不可站立区域。
- 除 Mask 外保持原镜头、构图、光照、天气、材质和元素位置不变。

角色任务要求：

- 使用同一角色参考条件和同一场景图/带 Mask 图。
- 角色主体必须落在 Mask 内，脚底接触目标元素附近的合理承载面。
- 只发生一个与目标元素相关的轻量动作，例如扶栏、探头、坐在台阶边、看向灯、站在桥头。
- 不增加第二只角色，不移动建筑或改变目标元素，不留下黑色 Mask。

### 7. 输入与输出命名

每个实验单元保存：

```text
scene.png
mask_input.png
mask_output.png
character_output.png
prompt-mask.txt
prompt-character.txt
run.json
review.json
```

命名格式为：`Gxx-Ey-Rz-*`。`run.json` 至少记录模型、尺寸、质量档位、请求时间、输入文件哈希、输出文件哈希和错误信息。

### 8. 人工审核

每张 Mask 图和对应角色图分别审核，不用单一自动指标代替人工判断。

Mask 审核维度（1–5 分）：

- 中心是否落在目标元素的合理角色落位区；
- 固定尺寸是否覆盖合理角色体积；
- 是否覆盖目标元素主体；
- 是否误覆盖另一个特征元素或不可站立区域；
- 视觉上是否能被后续编辑模型明确理解。

角色审核维度（1–5 分）：

- 角色是否存在且身份可辨认；
- 角色主体是否完全位于 Mask 区域；
- 脚底、比例和地面关系是否自然；
- 是否与目标元素形成明确且唯一的互动；
- 场景构图、画风、光照和目标元素是否保持。

每个实验单元记录 `mask_score`、`character_score`、`mask_overflow`、`element_damage`、`identity_drift` 和一句失败原因。两轮中至少一轮 Mask 平均分 ≥4 且角色平均分 ≥4，才记为该元素“初步稳定”；8 组中至少 6 组的两个元素都达到该条件，才记为路线在本夹具上正向。

### 9. 坐标与自动指标（辅助）

人工评审之外，记录：

- Mask 圆心和半径（像素及归一化坐标）；
- 角色实际 bbox、脚底锚点和 Mask 覆盖率；
- 目标元素 bbox 与 Mask 的 IoU/中心距离；
- Mask 外背景差异；
- 两轮输出之间的 Mask 圆心方差和角色中心方差。

自动指标只帮助发现异常，不作为唯一验收依据，因为角色合理位置通常不是一个唯一像素真值。

## Testing Decisions

### 必须覆盖的外部行为

1. 同一元素重复两轮时，Mask 中心和尺寸不能出现明显漂移。
2. 不同形状元素分别测试时，Mask 不能被模型固定理解成任意位置的装饰圆。
3. 角色生成必须服从带 Mask 场景，而不是只根据文字 Prompt 自由选点。
4. Mask 外的目标元素、背景结构和第二特征元素应保持可识别。
5. 角色结果不能因为场景复杂度变化而系统性越界或缩放失控。

### 失败分类

- `mask_wrong_target`：Mask 没有指向目标元素。
- `mask_size_drift`：同组固定尺寸明显变化。
- `mask_covers_element`：Mask 压住了目标元素本体。
- `mask_invalid_ground`：Mask 落在水面、天空、悬空处或不可站立区域。
- `character_outside_mask`：角色主体越出 Mask。
- `character_identity_drift`：若叶睦身份、发型、体型或配色明显漂移。
- `background_drift`：Mask 外建筑、地形、纹理或光照被重绘。
- `interaction_mismatch`：角色没有和目标元素发生明确互动。
- `provider_failure`：请求失败、超时或结果无法解码。

### 与已有验证的关系

- Session 0 已验证的图片生成、图片编辑、多图合成和 Mask 局部编辑作为底层前置能力，不在本 Spec 重复做 Provider 对比。
- 本 Spec 新增验证“复杂自然场景中的固定大小 Mask 稳定性”和“带 Mask 角色编辑是否服从位置约束”。
- 本 Spec 不证明 VLM 自动规划坐标、不证明 Unity 坐标转换、不证明视频或音频路线。

## Out of Scope

- 生产级 Agent 编排、重试、计费、并发和资源服务。
- 自动训练 LoRA、专属检测器或大规模数据集。
- 连续视频、Sprite Sheet、音频、后置天气状态和 Unity 运行时。
- 让图片模型自动完成最终审美构图。
- 把黑色圆形 Mask 直接当作生产碰撞体或正式坐标协议。
- 对现实摄影原图进行直接复刻；候选只用于构图与元素研究。

## Further Notes

本实验的关键分界是：

```text
Mask 画得准 ≠ 角色一定遵守 Mask
角色落在 Mask 内 ≠ Agent 已经拥有可靠的坐标规划能力
一次成功 ≠ 两轮重复稳定
```

如果 Mask 稳定而角色不稳定，后续应优先研究编辑模型或确定性合成；如果角色稳定但 Mask 不稳定，应把位置规划改为视觉模型输出坐标后由程序绘制 Mask；如果两者都不稳定，继续扩大场景数量没有意义，应先换输入形式或模型路线。

## 实验结果（2026-08-18）

全量实验已完成：20 张公开风景候选、8 个任务组、32 个实验单元、32 张 Mask 输出和 32 张角色输出均已落盘，共执行 64 次 `gpt-image-2` 图片调用。

自动测量显示，目标直径为 108px，而 32 个 Mask 的等效直径范围为 32.74–128.21px，中位数 64.96px，平均绝对误差 42.68px；只有 1/32 落在 108±10px 内。同一元素两轮的圆心漂移中位数为 41.05px，最大 85.75px；两轮直径差中位数为 10.50px，最大 62.79px。

人工复核显示：Mask 语义位置均分 4.31/5，可站立性均分 4.31/5，说明模型多数能找到合理地标区域；但固定尺寸均分仅 2.25/5。角色全部生成在黑圆附近，但严格服从 Mask 的均分仅 2.44/5，32/32 均有不同程度越出原圆；互动执行均分 2.44/5，24/32 被标记为互动不匹配。

按本 Spec 的冻结门槛，16 个元素中通过 0 个，因此路线整体不通过。该失败应精确解释为：

```text
语义位置选择具有正向能力；
固定像素 Mask、具体坐标复现、严格边界控制不稳定。
```

下一轮不再让图片模型绘制固定大小 Mask。建议让视觉模型输出语义位置或候选中心坐标，由确定性程序绘制 108px Mask，再单独验证 image-2 对程序 Mask 的角色生成服从性。

完整结果、逐项评分和接触表见 `reviews/result-summary.md`、`reviews/manual-review.csv`、`reviews/automatic-measurements.json` 与 `reviews/g01-review-sheet.jpg` 至 `g08-review-sheet.jpg`。
